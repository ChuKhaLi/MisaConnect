# Quickstart — `MisaConnect.ESign` slice 1 (PDF sign flow)

End-to-end walkthrough for a consumer developer adding the SDK to their .NET 8 service. Five minutes to first signed PDF.

> **Note**: This file describes the consumer-developer flow once slice 1 is implemented and the `MisaConnect.ESign` preview NuGet is published. Implementation is tracked in [tasks.md](./tasks.md) (generated by `/speckit-tasks`).

---

## 1. Prerequisites

- .NET 8 SDK.
- MISA eSign sandbox or production credentials: `userName`, `password`, `clientId`, `clientKey`, plus a MISA eSign **base URL** (sandbox URL is issued with your credentials; production is `https://esignapp.misa.vn`).
- At least one `ACTIVE` remote-signing certificate on the configured MISA account (check via MISA's eSign portal). If the account has no ACTIVE cert, `SignPdfAsync` throws `NoActiveCertificateException` immediately — no MISA call is wasted.

---

## 2. Install

```bash
dotnet add package MisaConnect.ESign --version 2.0.0-preview.1
```

The package transitively depends on `Microsoft.Extensions.{Configuration,DependencyInjection,Http,Options,Logging.Abstractions}`. No Polly, no third-party HTTP plumbing.

---

## 3. Configure

`appsettings.json` (or any `IConfiguration` source — env vars, Azure App Configuration, user secrets):

```json
{
  "Misa": {
    "ESign": {
      "Environment": "Sandbox",
      "BaseUrl": "https://<sandbox-host-issued-by-misa>/",
      "ClientId": "<your-clientId>",
      "ClientKey": "<your-clientKey>",
      "UserName": "<your-misa-user>",
      "Password": "<your-misa-password>",
      "Polling": { "Interval": "00:00:02", "TotalTimeout": "00:01:00" },
      "TransportRetry": { "MaxAttempts": 3, "BaseDelay": "00:00:00.200", "MaxDelay": "00:00:02" },
      "Errors": { "IncludeRawErrorMessage": false }
    }
  }
}
```

For sandbox secrets, use `dotnet user-secrets` (same pattern as eInvoice — see [docs/sandbox-setup.md](../../docs/sandbox-setup.md)):

```bash
dotnet user-secrets set "Misa:ESign:Environment" "Sandbox"
dotnet user-secrets set "Misa:ESign:BaseUrl" "https://<sandbox-host>/"
dotnet user-secrets set "Misa:ESign:UserName" "<user>"
dotnet user-secrets set "Misa:ESign:Password" "<pass>"
dotnet user-secrets set "Misa:ESign:ClientId" "<clientId>"
dotnet user-secrets set "Misa:ESign:ClientKey" "<clientKey>"
```

`Environment` must match the host of `BaseUrl` — the options validator refuses to start if they disagree.

## 4. Register

`Program.cs` (ASP.NET Core minimal API host shown; works the same in a console / worker / MAUI host):

```csharp
using MisaConnect.ESign.Client.DependencyInjection;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddMisaConnectESign(builder.Configuration);

// (Optional) swap any port BEFORE AddMisaConnectESign — your registration wins:
//   services.AddSingleton<ITokenCache, MyRedisTokenCache>();
//   services.AddSingleton<ICertificateSelector, PickByIssuerDnSelector>();

var app = builder.Build();
```

That single `AddMisaConnectESign(configuration)` call binds `MisaESignOptions`, registers all default port adapters, wires the typed `HttpClient` pipeline (transient-retry → bearer-auth → client-headers), and registers the `IMisaESignClient` facade.

## 5. Sign a PDF

```csharp
using MisaConnect.ESign.Client;
using MisaConnect.ESign.Client.Dtos;
using MisaConnect.ESign.Domain.Errors;

app.MapPost("/sign", async (IMisaESignClient esign, IFormFile pdfUpload, CancellationToken ct) =>
{
    using var ms = new MemoryStream();
    await pdfUpload.CopyToAsync(ms, ct);

    try
    {
        var result = await esign.SignPdfAsync(new SignPdfRequestDto(
            Pdf: ms.ToArray(),
            DocumentName: pdfUpload.FileName,
            SignerName: "Nguyễn Văn A",
            Location: "Hà Nội",
            Reason: "Phê duyệt hợp đồng dịch vụ",
            Contact: "nguyenvana@example.com",
            LogoImageBase64: Convert.ToBase64String(await File.ReadAllBytesAsync("logo.png", ct)),
            DataToBeDisplayed: "<p>Phê duyệt hợp đồng số 2026/05/18-01</p>",
            Page: 1,
            PositionX: 100, PositionY: 100, Width: 200, Height: 80,
            RenderingMode: 1,
            ShowSignedDate: true), ct);

        return Results.File(result.SignedPdf, "application/pdf",
            fileDownloadName: Path.GetFileNameWithoutExtension(pdfUpload.FileName) + ".signed.pdf");
    }
    catch (NoActiveCertificateException ex)
    {
        return Results.Problem(detail: "Bạn chưa có chứng thư số ACTIVE.", statusCode: 409);
    }
    catch (AuthenticationFailedException ex) when (ex.Requires2FA)
    {
        // MISA wants 2FA — slice 2 of the SDK adds first-class support.
        return Results.Problem(detail: "MISA yêu cầu xác thực hai lớp; cần bật slice 2.", statusCode: 401);
    }
    catch (SignTerminalStateException ex)
    {
        return Results.Problem(detail: $"Giao dịch ký {ex.TerminalStatus}: {ex.RawCode}", statusCode: 422);
    }
    catch (SignTimeoutException ex)
    {
        return Results.Problem(detail: $"Quá thời gian chờ ký (transactionId={ex.TransactionId}).", statusCode: 504);
    }
    catch (ESignTransportException ex)
    {
        return Results.Problem(detail: $"MISA tạm thời không phản hồi (sau {ex.AttemptCount} lần thử).", statusCode: 503);
    }
});
```

That's it. One DI registration + one method call.

## 6. What the SDK does on your behalf

Behind that one `SignPdfAsync` call, the SDK:

1. **Looks up cached tokens** by the key `userName|clientId|baseUrlHost`. If hot → skip step 2.
2. **Logs in** via `POST /api/auth/api/v1/auth/login-api`. Caches `remoteSigningAccessToken` + `refreshToken` for `expiresIn` seconds.
3. **Lists certificates** via `GET /external/esrm/service/general/api/v1/Certificates/by-userId` (with `AuthorizationRM` header). Filters to `keyStatus == ACTIVE`. If empty → `NoActiveCertificateException`.
4. **Picks one cert** via the registered `ICertificateSelector` (default: first ACTIVE in MISA's response order).
5. **Hashes the PDF** via `POST /external/esrm/service/document/api/v1/documents/hash` (SHA256, server-side).
6. **Submits the digest** via `POST /external/esrm/service/signing/api/v1/Signing/hash`. Captures `transactionId`.
7. **Polls** `GET /external/esrm/service/signing/api/v1/Signing/status/{transactionId}` every `Polling.Interval` until `SUCCESS`/`FAILED`/`CANCELLED` or `Polling.TotalTimeout`. The end user confirms the sign on their **MISA eSign mobile app** during this window.
8. **Attaches the signature** via `POST /external/esrm/service/document/api/v1/documents/attachment`. Returns the signed PDF bytes.

If anywhere in 2–8 a request returns 401, the SDK refreshes the token via `POST /webdev/api/auth/api/v1/auth/refreshtoken` once and retries the failing request once. Concurrent calls observing 401 for the same cache key share one refresh.

If anywhere in 2–8 a request returns 429 / 5xx / connection-failure / timeout, the SDK retries up to `TransportRetry.MaxAttempts` with exponential backoff + jitter (honoring `Retry-After` on 429).

If `documents/hash` already returned a `transactionId` before a transient failure, the retry resumes polling **that same** `transactionId` — there is no risk of double-signing.

## 7. What's logged (and what isn't)

The SDK emits one Information log per MISA call with: `{Endpoint}`, `{Method}`, `{StatusCode}`, `{CorrelationId}`, `{DurationMs}`. On terminal failures it emits one Error log with `{ExceptionType}`, `{RawCode}`, `{CorrelationId}`, and a scrubbed `{Detail}`.

The SDK **never** logs by default:
- Access tokens or refresh tokens.
- The `AuthorizationRM` header value.
- Certificate private-key material (`certificate`, `certificateChain[*]`).
- Raw PDF bytes (`FileToSign`, `documentBytes`, `digest`, `sh`).
- The signer's name, email, or phone number (PII).
- The MISA `userMsg`/`devMsg` strings — unless `MisaESignOptions.Errors.IncludeRawErrorMessage = true`, and even then only on the surfaced exception, never in log lines.

Correlation IDs are always logged and always present on exceptions, so you can cross-reference with MISA's support when something goes wrong.

## 8. Common errors and how to react

| Exception | What happened | What to do |
|-----------|---------------|------------|
| `NoActiveCertificateException` | The user has no `ACTIVE` cert on MISA. | Direct them to https://esign.misa.vn/ to provision one. |
| `AuthenticationFailedException` (`Requires2FA = true`) | MISA returned errorCode 122 — needs OTP. | Slice 2 (out of scope here) adds first-class 2FA. For now, surface the message. |
| `AuthenticationFailedException` (`Requires2FA = false`) | Bad credentials, account locked, or refresh-token rejected. | Re-issue credentials or have the user re-log-in to MISA. |
| `SignRejectedException` (`RequiresUserCertSetup = true`) | The user hasn't paired their MISA eSign account with the cert yet. | Direct them to `https://misajsc.amis.vn/wesign/setting/individual/connectesign`. |
| `SignTerminalStateException` (`TerminalStatus = FAILED`) | MISA rejected the sign after submission. | `ex.RawCode` + `ex.Detail` describe why. Often a cert revocation or duplicate-tx issue. |
| `SignTerminalStateException` (`TerminalStatus = CANCELLED`) | The user (or MISA admin) cancelled the sign request on the mobile app. | Surface that to the requester; do not retry automatically. |
| `SignTimeoutException` | The user didn't confirm within `Polling.TotalTimeout`. | The transaction is left as-is on MISA's side — they may still confirm. You may extend the timeout in config and try again, but the SDK does not auto-resume. |
| `ESignTransportException` | MISA's API is degraded (429/5xx) and the transport-retry budget is exhausted. | Treat as transient — back off and try again. Check `ex.LastStatusCode` and `ex.AttemptCount` for diagnostics. |
| `ESignException` (any other) | Unmapped MISA error. | `ex.RawCode` is MISA's verbatim `errorCode`. Bring it to MISA support with `ex.CorrelationId`. |

## 9. Testing your integration

### 9.1. Unit tests (your code)

Mock `IMisaESignClient` directly — slice 1 keeps the facade dependency minimal:

```csharp
var fake = new Mock<IMisaESignClient>();
fake.Setup(x => x.SignPdfAsync(It.IsAny<SignPdfRequestDto>(), It.IsAny<CancellationToken>()))
    .ReturnsAsync(new SignPdfResultDto(
        SignedPdf: TestData.SignedPdfBytes,
        TransactionId: "tx-123",
        CertificateKeyAlias: "cert-alias",
        CompletedAtUtc: DateTimeOffset.UtcNow));
```

### 9.2. Integration tests (against the SDK)

Use the SDK's own integration test pattern (see `tests/MisaConnect.ESign.IntegrationTests/`):

- **`[SandboxFact]`** tests skip unless `MISACONNECT_ESIGN_SANDBOX_*` env vars are present and the sandbox host is reachable. Use these for live end-to-end coverage.
- **`EsignFake/`** is an in-repo deterministic HTTP host — point your integration tests at it for fully offline E2E coverage (refresh-stampede counting, polling state machine, terminal-state mapping).

---

## 10. Going to production

Flip three things:
- `Misa:ESign:Environment` → `Production`
- `Misa:ESign:BaseUrl` → `https://esignapp.misa.vn/`
- Sandbox credentials → production credentials

The options validator refuses to start if the environment and base-URL host disagree, so misconfiguration fails fast.
