## Decisions (don't relitigate)
- **Spec Kit:** retired. Use the superpowers design → plan flow for all work, and add no new `specs/NNN-*` slices.
- **`DeliverValidationFailuresToHook`:** defaults to `true` in 2.x, so there is no silent change in a minor release. `false` gives the TS ruling R12, and the default flips in 3.0.
- **Webhooks:** the body is only a trigger. MISA's `Signing/status` decides, so a FAILED webhook while MISA reports SUCCESS is signed (TS parity).
- **Hook exceptions:** an integrator-hook exception on success or terminal delivery propagates. The success is cached first.
- **`FinalizeFromWebhook`:** its 2.4 constructor is removed in 2.5.0. Signed off by merging; it needs the wire client for `Signing/status`. `HandleWebhook` and `BeginSign*` keep their 2.4 constructors as `[EditorBrowsable(Never)]` overloads.
- **Static mode:** skips `IWebhookCredentialsResolver`; TS always calls it.
- **Dependabot:** "nobody uses the SDK yet", so major bumps such as Microsoft.Extensions 10 are merged freely.
- **`Xunit.SkippableFact`:** pinned at 1.4.13; Dependabot ignores ≥ 1.5.0.
- Plus the earlier decisions from the superseded handoff:
  - `tokenFingerprintSecret`;
  - no history rewrite;
  - the PR workflow;
  - `dotnet format` in CI.

## Gotchas
- **Auto mode blocks:**
  - `gh pr merge` for PRs the user did not explicitly ask to merge;
  - `gh run rerun`;
  - `@dependabot …` ChatOps comments.

  Give the owner the exact `! …` command.
- **Repo settings:** `allow_auto_merge` is false and `main` has no branch protection, so `gh pr merge --auto` silently does nothing. To merge on green, watch the checks and then merge.
- **GitHub 5xx:** GitHub returned 500/502 several times on 2026-11-05. Check the real state (`gh pr view`, `gh release view`) before retrying; the action may already have happened.
- **Release notes:** `release.yml` takes them from `## [<version>]` in the CHANGELOG at the tagged commit. Move `[Unreleased]` to a version section **before** tagging.
- **Stale IDE diagnostics:** Windows IDE/LSP diagnostics are often stale (CS0103/CS0246 on newly added types). Trust `dotnet build`.
- **CHARSET diagnostics:** a CHARSET diagnostic from `dotnet format` means non-UTF-8 bytes; subagents once wrote cp1252 em-dashes. ENDOFLINE/WHITESPACE noise is expected on Windows CRLF checkouts.
- **xunit discovery traps:** a fact attribute that inherits `SkippableFactAttribute`, or takes constructor arguments, is silently not discovered.
- **Bash heredocs:** a quoted heredoc containing an apostrophe in a `$(...)`/`'…'` context broke once. Use the Write tool for long files.
